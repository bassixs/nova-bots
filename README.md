# NOVA lab — Чат-боты в MAX

Статическая посадочная с HTML, CSS и JavaScript без клиентского фреймворка. Основные тексты и все шесть сценариев присутствуют в исходном HTML. Публичный адрес: `https://nova-bots.ru/`; прежний путь `/services/max-bots/` перенаправляется на главную (301).

## Работа с проектом

Нужен Node.js 20+. Зависимостей для сборки нет.

```sh
node scripts/build.mjs
node scripts/serve.mjs
```

Предпросмотр: `http://127.0.0.1:4173/`. После изменений выполнить сборку и обновить страницу. Для размещения на статическом хостинге используется содержимое `dist/`.

`src/components.mjs` содержит переиспользуемые шапку, подвал, кнопки, карусель и секции. `src/scenarios.mjs` — содержание примеров. `src/style.css` — базовые стили, `src/experience.css` — анимации, `src/glass.css` — стеклянная тема и геометрическая типографика, `src/atmosphere.css` — композиция первого экрана, оптическое стекло и светящаяся SVG-дуга. `src/app.js` — взаимодействия. Manrope и Unbounded хранятся локально; лицензии включены.

## Настройки перед рекламным запуском

Все публичные настройки находятся в `site.config.mjs`:

- `origin` — публичный HTTPS-домен. Из него создаются canonical, og:url и sitemap.xml.
- `indexable` — управление индексированием через robots.txt и HTML. Для опубликованного домена включено.
- `title`, `description`, `ogTitle`, `ogDescription`, `ogImage` — SEO, Open Graph и Twitter Card.
- `sitemapPaths` — список канонических путей для sitemap. При добавлении отдельной индексируемой страницы внести её путь сюда.
- `contacts.email`, `contacts.phone`, `legalName`, `legalDetails` — реальные контакты и реквизиты. Пустые значения не отображаются.
- `contacts.maxUrl`, `contacts.telegramUrl`, `contacts.vkUrl` — публичные HTTPS-ссылки для MAX, Telegram и ВКонтакте. Пустая или некорректная ссылка оставляет кнопку неактивной с пояснением.

После изменения настроек повторить сборку. Формы заявки нет: посетитель сам выбирает внешний канал связи.

### Яндекс Метрика

ID счётчика задаётся **в одном месте** — переменной окружения `NOVA_METRICA_ID` при сборке. Например, в PowerShell:

```powershell
$env:NOVA_METRICA_ID='ВАШ_ЧИСЛОВОЙ_ID'
node scripts/build.mjs
```

Без ID скрипт Метрики не загружается, а `trackGoal()` безопасно ничего не делает. После указания ID пересобрать и опубликовать `dist/index.html`, `dist/assets/app.js` и `dist/assets/analytics.js`; создать в интерфейсе Метрики цели типа «JavaScript-событие» с идентификаторами `hero_cta_click`, `scenario_change`, `scenario_6_reached`, `scenario_final_cta`, `contact_max`, `contact_telegram`, `contact_vk`, `faq_open`. Для `scenario_change` передаётся только `scenario_id` 1–6, для `faq_open` — `faq_id` 1–4. Автоматическая смена слайда не считается действием пользователя и не отправляет цели. Персональные данные в параметры целей не передаются.

Внутренние ссылки-якоря оставляют входящие UTM в URL страницы. Цели внешних мессенджеров фиксируются на исходной странице перед открытием канала, поэтому исходная рекламная метка остаётся в контексте визита Метрики; внешние URL не переписываются.

### Индексация и графика

Сборка создаёт `robots.txt`, `sitemap.xml`, JSON-LD Organization/Service, отдельную 404-страницу и app icons. На хостинге `.htaccess` перенаправляет HTTP, альтернативный host, `/index.html` и прежний путь на `https://nova-bots.ru/` и отдаёт 404 с правильным статусом. OG-изображение 1200×630 и иконки можно пересоздать командой `python scripts/generate-brand-assets.py` (нужен Pillow); исходный фирменный логотип остаётся в `public/assets/nova-logo.png`. После публикации sitemap следует отправить в панели Яндекс Вебмастера и Google Search Console.

## Размещение на Host-0

Сайт размещён в каталоге `/www/nova-bots.ru` аккаунта `u3646325` в ispmanager. В корень загружается **содержимое** `dist/`, а не папка `dist` целиком. Публичный адрес — `https://nova-bots.ru/`. Старый стандартный файл хостинга сохранён на сервере как `index.hosting-backup.html`. Доступы к хостингу и GitHub в репозитории не хранятся.

## Способы связи

Блок предлагает MAX, Telegram и ВКонтакте. Переключение вкладок остаётся на странице; внешний сервис открывается только по нажатию кнопки выбранного канала. Кнопки ведут на адреса из `site.config.mjs`.

## Поведение и проверки

Вступительная заставка использует облегчённую веб-версию предоставленного `промо.mp4`: `public/assets/nova-intro.mp4` (4,11 секунды, 1920×1080, 60 fps, без ненужной звуковой дорожки, около 0,7 МБ вместо 19,7 МБ). Исходник сохранён в корне рабочей папки. При первом открытии сайта в каждой вкладке ролик запускается без звука и без обрезки, затем плавно открывает страницу без второй длинной анимации появления hero. Повторная загрузка в той же вкладке пропускает заставку; `/?intro=1` воспроизводит её повторно, а `/?intro=0` пропускает. Кнопка «Пропустить заставку» и Escape завершают её сразу. При reduced motion видео не загружается. Ошибка воспроизведения или загрузка без прогресса дольше 3,5 секунды открывают сайт автоматически. Локальный сервер поддерживает диапазоны байтов для MP4.

Первый экран: предложение слева, телефон с диалогом и отдельная стеклянная панель сотрудника справа. Синяя SVG-дуга просвечивает через панель сотрудника; отдельного фонового видео нет. На узких экранах блоки идут последовательно. В первом сценарии показаны иллюстративные карточки товаров; источник изображения и промпт описаны в `docs/image-assets.md`.

Автопрокрутка каждые 5,5 секунды, ручное переключение, клавиши ←/→/Home/End, свайп по горизонтали. После ручного переключения автосмена отключается до перезагрузки страницы. Кнопки паузы и запуска нет. Наведение, фокус, скрытая вкладка и уход hero с экрана приостанавливают автопрокрутку. Reduced motion отключает её и фоновое движение. При автоматической смене фокус не перемещается. На мобильном панели идут последовательно.

Использован логотип, предоставленный пользователем: `public/assets/nova-logo.png`. Цвета и свечение страницы согласованы с ним. В карусели четыре бизнес-сценария и два для администрации.


## Визуальный слой — dark optical glass

Фон `#08090D`, световые синие и фиолетовые акценты и полупрозрачные поверхности определены в `src/atmosphere.css`. Основная CTA белая. Телефон имеет более плотный материал, панель сотрудника — более прозрачное стекло с blur 34px. Вступление раскрывает заголовок по строкам и заканчивается за 1,5 секунды. Сценарии переходят независимо для телефона и панели сотрудника с задержкой 100ms, без bounce; дуга перемещается на несколько пикселей, индикатор плавно переходит к новой позиции.

Этапы представлены timeline: один passive scroll listener объединяет измерения и обновления в requestAnimationFrame. FAQ сохраняет native details/summary и плавно раскрывается в обе стороны. Контакты расположены в единой стеклянной поверхности. Тексты, порядок разделов, шесть сценариев и ссылки каналов сохранены. Для reduced motion отключены автосмена, вступление и декоративное движение; есть fallback для reduced transparency и отсутствия backdrop-filter. Изображения и шрифты загружаются локально, новых библиотек нет.


## Финальная доводка материалов и движения

`src/polish.css` уточняет текущую композицию: три плотности тёмного стекла, тонкое ядро SVG-дуги с bloom и ambient, статичный monochrome grain 1,6%, перспективу демо и мобильное наложение панели сотрудника на нижний край корпуса телефона. На телефоне последовательность: заголовок и описание → CTA → демо. Тексты и сценарии не изменены.

Переход сценария завершается за 720ms; входящая панель сотрудника следует через 100ms, исходящая — через 80ms. Содержимое проявляется каскадом, progress-индикатор и свет перемещаются синхронно. Стрелки клавиатуры и touch-swipe сохранены. На крупных стеклянных поверхностях отражение мягко следует за курсором, а параллакс работает только внутри правой демо-зоны: телефон до 4,5px, панель до 6,3px, дуга до 2,5px, фон до 1,5px. Pointer listeners используют событийный requestAnimationFrame, без постоянного цикла; blur поверхности не анимируется непрерывно. Реакции курсора отключены для узких экранов, touch и reduced motion.

Timeline различает предстоящие, активные и пройденные этапы. Контактные панели затухают и проявляются в общей grid-ячейке с зарезервированной высотой; быстрый повторный выбор отменяет предыдущую анимацию. Только выбранный канал доступен клавиатуре и screen reader.


Проверка финальной доводки: desktop 1920×1080 и 1440×900, mobile 390×844 и 430×932. Проверены края и переносы текста по всей странице, шесть сценариев, повторные быстрые переходы, клавиатурные стрелки, меню, FAQ и три канала связи. На мобильных высота демо сохраняется при смене сценария; контактная поверхность сохраняет высоту при смене канала. Новые внешние зависимости и медиафайлы не добавлены.


Точечная доработка демо: почти непрозрачный MAX-интерфейс, прозрачная панель результата, небольшая editorial-подпись. Номер и название меняются через fade/mask; шесть кликабельных линий различают пройденный, активный и будущий сценарии. Любой pointerdown внутри демо отключает автосмену, наведение и фокус временно её приостанавливают. В шестом сценарии добавлена ссылка к #contact; седьмого сценария и новых секций нет. Высота демо резервируется для самого высокого сценария.

Финальная настройка демо: смещение ±24px, blur 8px, scale .98, спокойное появление панели сотрудника через 100ms после MAX. CTA внутри шестого сценария содержит вопрос, пояснение и ссылку к контактам; общая нижняя часть showcase остаётся навигационной.


## Showcase в первом desktop viewport

На ширине от 1151px `.scenario-carousel` имеет высоту `min(72svh, 780px)`. `.demo-stage` получает оставшееся место после `.showcase-footer`; ResizeObserver вписывает в него общий canvas всех шести сценариев одним пропорциональным transform. Измеряется естественная высота всего canvas, а не активного сценария. Телефон растягивается по общей grid-строке, сообщения не сжимаются и не прокручиваются внутри корпуса. Заголовок страницы и controls не масштабируются.

Название, стрелки, progress и пояснение находятся в постоянном footer компонента. На desktop высотой до 800px уменьшены верхний отступ hero и внутренние отступы панели сотрудника. Editorial остаётся абсолютно позиционированной над интерфейсами. На mobile/tablet масштабирование отключено, сохранена прежняя последовательная компоновка.

Проверены все шесть сценариев на каждом размере, реальные клики по progress при scrollTop=0:

| 1440×900 | 777px | Нет | Нет |

Проверен возврат с mobile 390×844 к desktop: scale пересчитывается, на mobile transform отсутствует и горизонтального переполнения нет. Ошибок в консоли браузера не обнаружено.

## Оптическая сцена NOVA

Правый showcase получил более широкий общий canvas без изменения высоты hero. Телефон и тёмная стеклянная панель слегка пересекаются; локальный свет дуги виден на гранях, за стеклом и в едва заметных размытых оптических формах. Во время первого появления телефона стекло раскрывается с небольшой задержкой, затем сцена остаётся спокойной. Тексты, шесть сценариев и механика управления не изменены.

После визуальной доводки повторно проверены все шесть сценариев на 1920×1080, 1440×900, 1366×768 и 1280×720: progress и стрелки видны в первом viewport, высота hero и положение controls неизменны, сообщения не перекрываются и не обрезаются. На 390×844 и 1024×768 нет горизонтального переполнения. Консоль браузера без ошибок.
